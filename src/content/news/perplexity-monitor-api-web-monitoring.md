Perplexity از Monitor API رونمایی کرده است؛ ابزاری برای پایش زمان بندی شده وب که تغییرات مرتبط را از طریق وب هوک به برنامه ها و عامل های هوش مصنوعی می فرستد. این API به توسعه دهندگان امکان می دهد به جای اجرای مکرر جست وجوها و نگهداری کدهای جداگانه برای شناسایی تغییرات، یک پایشگر بسازند و فقط هنگام پیدا شدن نتیجه مهم به روزرسانی دریافت کنند.

## Monitor API چگونه کار می کند؟

توسعه دهنده با یک درخواست API، عبارت جست وجو، هدف پایش، زمان بندی و نشانی وب هوک را تعیین می کند. این سرویس دو حالت دارد: پایش وب، که جست وجوهای Perplexity در وب و خبرها را در فاصله های زمانی مشخص اجرا می کند، و پایش صفحه، که تغییرات حداکثر ۱۰ صفحه را دنبال می کند.

در پایش صفحه، اجرای نخست نسخه پایه را ذخیره می کند و تغییرهای بعدی را به شکل تفاوت متنی برمی گرداند. صفحه هایی مانند فهرست قیمت، گزارش تغییرات محصول یا سیاست های یک شرکت می توانند برای این کار انتخاب شوند. هر پایشگر در اجراهای بعدی ادامه بررسی قبلی را دنبال می کند و نتیجه های تکراری را کنار می گذارد.

## مدل تصمیم گیری و زمان بندی

Perplexity می گوید مدل تصمیم گیری خودش نتیجه ها را با هدفی که توسعه دهنده به زبان طبیعی مشخص می کند، ارزیابی می کند. نتیجه های جست وجوی وب از نظر ارتباط، اعتبار منبع، تازگی و زمان انتشار سنجیده می شوند؛ تغییرات صفحات هم بر اساس اهمیتشان برای هدف تعیین شده بررسی می شوند. سرویس فقط وقتی به روزرسانی می فرستد که نتیجه از آستانه های تعیین شده عبور کند و همراه آن امتیاز اطمینان ارائه می دهد.

توسعه دهندگان می توانند آستانه هر معیار را جداگانه تغییر دهند و هدف پایش را بدون ساخت دوباره آن به روزرسانی کنند. زمان بندی از هر ۱۵ دقیقه تا هفته ای یک بار قابل تنظیم است و امکان استفاده از زمان بندی سفارشی cron نیز وجود دارد. پایشگرها را می توان از طریق API یا کنسول API متوقف کرد، از سر گرفت یا به صورت دستی اجرا کرد. وب هوک ها امضا می شوند و در صورت بروز خطای موقت، Perplexity ارسال را دوباره امتحان می کند.

## قیمت و زمان عرضه

Monitor API اکنون از طریق API و کنسول API در دسترس است و با همان کلید مورد استفاده برای Search، Context و Agent API کار می کند. هزینه پایش وب ۱ دلار به ازای هر ۱۰۰۰ اجرای موفق است. پایش صفحه نیز به ازای هر ۱۰۰۰ URL واکشی شده ۱ دلار هزینه دارد.

## چرا این خبر مهم است؟

این API می تواند اجرای عامل هایی را ساده تر کند که باید تغییرهای مشخصی را در وب دنبال کنند؛ برای مثال، پایش دورهای جذب سرمایه و تغییرهای نیروی انسانی شرکت ها، قیمت رقبا یا مقررات تازه. به جای آنکه عامل پیوسته جست وجو کند، سرویس می تواند فقط هنگام شناسایی تغییر مرتبط آن را بیدار کند.

Perplexity می گوید در آزمون داخلی اولیه خود، طی هشت ساعت ۶۳ صفحه تازه و مرتبط تحویل داده است؛ Firecrawl در همان آزمون ۲۰ نتیجه، Exa پانزده نتیجه و Parallel Core و Lite هرکدام ۱۰ نتیجه ارائه کردند. این مقایسه بر پایه ۶۰ موضوع و تنظیمات هر سرویس انجام شد و یک مدل جداگانه ارتباط و تازگی نتیجه ها را امتیازدهی کرد. Perplexity این ارقام را نتایج داخلی اولیه توصیف کرده است.
